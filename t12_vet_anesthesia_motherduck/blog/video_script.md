Hi everyone. A couple of months ago, I ran into an interesting data problem. My fiancée is a veterinarian, and she was running a research study on a new anesthetic used during surgeries on dogs. When the trials wrapped up, she had a mountain of data to analyze. Quick note before we start: every record you'll see in this video is dummy data.

The catch was how that data was recorded. Every patient had a paper-style anesthesia sheet that got sent over as a PDF. At least it was all typed and not handwritten. But the sheet template also changed a little between trial dates.

And this was not simple data. Each record had timestamped medications and doses, timestamps for every surgical step and milestone, clinical remarks, and vitals like heart rate, blood pressure and respiration, recorded all the way through the procedure. That was never going to fit in a single Excel file running on Windows Vista. We needed to bring in the heavy artillery.

I wanted one workflow that could ingest all of these files, combine them, clean and standardize them, dedupe them, and reshape everything into something you could actually analyze. It had to work as a one-time migration, but also run again whenever new trial data came in. And once the tables were in good shape, I needed an easy way to share them and answer questions from the statisticians quickly. So I went with Tabsdata and MotherDuck. Tabsdata handles ingestion, transformation and orchestration. MotherDuck handles storage, querying and analytics.

First, I had to get the data out of the PDFs. I extracted the text from each PDF, then had an LLM read that text and find a loose schema of the fields that showed up across patients. From those fields, I designed a star schema for how I wanted the final data organized. Then the LLM converted each patient's text into a set of CSVs matching that structure. That's about as far as I was willing to trust an LLM with my data. We still went through a lot of those CSVs by hand, fixing missed values and formatting issues.

Now here's where Tabsdata comes in. I had almost 180 CSV files. Every dataset was split up, one file per animal, so instead of one vitals table, I had a separate vitals file for every patient. The data types were a mess too. Somewhere between the PDFs, the text extraction and the CSV generation, integers, decimals, booleans, dates and timestamps had all turned into strings. And the schemas didn't match. Some patients were missing columns, and others had extra ones.

So in Tabsdata, I built a publisher that uses wildcard matching to find every CSV for a dataset, lines up their schemas, concatenates them into one table, and stores it as a versioned Tabsdata table. Each run only picks up newly added files, and because the tables are versioned, I can see exactly when each batch landed. That gave us our bronze tables.

The data in them was still messy, so next came silver. Silver does four things. It casts every field back to its real type, like dates, timestamps, integers, floats and booleans. It renames columns to consistent snake case, because the originals mixed camel case, spaces and symbols. It cleans up values, like splitting a dose of 2.9 milligrams into a number column and a unit column, and turning blanks into proper nulls. And it dedupes the records that repeat across patient files, like the vets and the owners.

Gold takes that clean data and joins it into the fact and dimension tables from the star schema. Every event, whether it's a drug, a lab, a remark or a vitals reading, gets keys that tie it back to the patient, the owner and the date. I also added rollups for the metrics we kept asking for, like counts per case.

Finally, I needed somewhere to publish the data, share access, and run queries whenever a new request came in. MotherDuck took about ten minutes to set up. Then I built a custom Tabsdata connector for MotherDuck that creates the database and tables, and loads the gold tables into them automatically every time gold updates.

From there, MotherDuck is a great place to work. I can write SQL in notebooks, use the built-in AI to help debug queries, and download results without leaving the browser. So when a statistician asks for a new slice of the study, like blood pressure during each surgical step, I don't go back to the CSVs or build another export. The clean data is already sitting in MotherDuck, ready to query. Thanks for watching.
